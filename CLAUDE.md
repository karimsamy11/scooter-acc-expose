# Scooter ACC Exposé and Engineering Lab — Claude Code Instructions

This is the **public** repository of Scooter ACC Drive Assist, a research prototype of adaptive distance assistance for standing e-scooters, in simulation only. It is published with GitHub Pages at https://karimsamy11.github.io/scooter-acc-expose/. The engineering project itself (code, requirements, hazards, findings, costs) is in a separate **private** repository and must never be copied here.

## Engineering Lab
Purpose: invite engineers to challenge the reference architecture ("challenge the architecture, not the developer").

- **Flow:** three questions (idea and why it is better are required; how to test it is optional) → optional AI review → consent dialog → GitHub opens a new Discussion in the category "Engineering proposals" (slug `engineering-proposals`, created 2026-10-18; renaming it breaks the submit link) with the proposal filled in. The visitor publishes it under their own account. The chat is never included.
- **AI:** runs in the visitor's own [Ollama](https://ollama.com). No server, no API keys, no cost. The page talks only to loopback addresses (`lab/ollama.js` refuses anything else; CSP `connect-src` allows only `127.0.0.1`/`localhost`). It tries the temporary lab-session port 11435 first, then Ollama's normal port 11434.
- **Visitor setup** (also on the page): `ollama pull qwen2.5:7b` (or `qwen2.5:3b` on small machines), then a lab session that only this site may use while its window is open: `OLLAMA_HOST=127.0.0.1:11435 OLLAMA_ORIGINS=https://karimsamy11.github.io ollama serve`. Exact origin, never `*`, never `0.0.0.0`. Chrome and Edge then ask for local-network permission.
- **AI review sections:** Architecture, Requirements check (FR-1 to FR-8, "addressed by …" or "open"), Risks and assumptions, Validation suggestions, Open questions. It never overwrites the visitor's answers and only fills empty ones.
- **Pass criteria guard:** `guardCriteria` in `lab/proposal.js` replaces any AI pass criterion whose numbers do not come from the fixed requirements (3 m + 2 s gap, 20 km/h, 3 s TTC, 20 ms, 50 Hz) or the visitor's own answers with "To be defined and validated".
- **Safety of rendering:** visitor and model text is inserted as text only (`lab/render.js`, no `innerHTML`). Visitor text is passed to the model as data, not instructions.
- **Owner review:** proposals are labelled New / Needs clarification / Under review / Accepted for experiment / Rejected with reason. Nothing is accepted or changed automatically.

## Rules for this repository
- Public information only. The brief, prompt, tests and pages must not contain private findings, requirement or hazard IDs, source code, cost figures or private repository details. Check before every push.
- The AI must never claim that an untested design is safe, validated, compliant, certified or road legal, and must never suggest automatic braking, public-road tests or bypassing brakes. Keep these rules in `system-prompt.md`.
- The brief and the prompt change only with the owner's approval. After changing them, run the tests and try a real model.
- Do not change the exposé design or functionality here; the page is generated elsewhere.
- Git author for the owner is "Karim Samy". Personal notes go in `CLAUDE.local.md`.

## Testing
- `python tests/run_tests.py` serves the site on 127.0.0.1:8765, starts mock Ollama servers (one allows the page, one refuses it like an unconfigured Ollama), and runs the unit and end-to-end pages in headless Edge, Chrome or Firefox (`BROWSER=/path/to/browser` to choose).
- Current result (2026-10-18): 25/25 (unit 13, end-to-end 8, request checks 4) in Edge and Chrome on Windows, and Chrome on Linux in CI (`lab-tests`).
- Also tested by hand with real Ollama 0.40.6: qwen2.5:7b gives a useful engineering review (3–5 min per answer on a laptop with a 4 GB GPU); qwen2.5:3b answers in 15–30 s but its engineering judgement is weak. From the live https page, Edge reached a lab session after the local-network permission; Ollama's normal port and other websites were refused.

## Known limitations
- Firefox and Safari are not tested on real hardware. Safari may block https pages from calling a local server; the page then offers running the Lab locally (`python -m http.server 8000 --bind 127.0.0.1`, open `http://localhost:8000/lab/`).
- Phones cannot run the local AI; the three-question form works without it.
- While a lab session runs, every page under `https://karimsamy11.github.io` can use that Ollama (run, download or delete models). The setup text says so; the session ends when its window closes.
- Small models can still overclaim or be generic; visitors edit the review before submitting, and the owner decides.
- giscus comments are prepared in `lab/lab.js` (`GISCUS`) but not configured.
